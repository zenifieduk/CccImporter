## Editorial conventions for Chronicle articles

These are saved at
`~/.claude/projects/-Users-james-Desktop-CLASSICCC/memory/preference_no_em_dashes_in_articles.md`
but the new session won't have that file. Key rules:

1. **No em dashes (`—`)**. The user finds them an AI-writing tell. Use
   commas, parentheses, colons, semicolons or full stops as appropriate
   to the grammatical job. Don't lazily comma-splice everywhere.
2. **No inline `**bold**` mid-paragraph**. The chronicle CSS rule
   `.chronicle-post p strong` is intentionally styled as a block-level
   pseudo-header (border-bottom, 3.5rem top margin). Use `**text**` only
   when it should be a standalone sub-header on its own line. For inline
   emphasis, use italics `*text*` or rely on sentence structure.
3. **Em dashes in event/theme names** (e.g. "The Rivals — Epic Racing
   Duels") get replaced with colons (`The Rivals: Epic Racing Duels`).
4. **No `— James Williams` signoff lines** at the bottom of articles.
   The frontmatter byline already credits the author.
5. **Voice**: warm, opinionated, written as if to an enthusiast peer.
   Look at the three new articles above for the tone reference.

## Article frontmatter shape

```yaml
---
title: "..."
date: 2026-MM-DD
tags: ["News", "Events"]
excerpt: One-line description used in the chronicle index card and OG.
featuredImage: /assets/images/news/article-slug.avif
featured: true
author: James Williams

---
```

## Hero image generation

Higgsfield MCP (`mcp__f7d1c3da-fbae-4a56-955e-6aed217164bf__*`) is the
preferred path. ALWAYS use model `gpt_image_2` (16:9, resolution `2k`,
quality `high`) for article heroes. Do NOT use `soul_location` or any
other model: the user considers the soul_location output poor, and on
2026-06-07 had all three June 2026 heroes (H1 market report, Goodwood
FoS preview, Goodwood Revival preview) regenerated from soul_location
to gpt_image_2. Download the PNG `rawUrl`, convert to AVIF with sharp:

```bash
node -e "require('sharp')('input.png').resize(1920).avif({quality:60,effort:6}).toFile('output.avif')"
```
